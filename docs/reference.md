# 配置与排查参考

日常运行步骤见[使用说明](usage.md)。以下命令中的场次目录和角色名请替换为实际值。

## 模型接入

在 `configs/models.yaml` 中，`provider` 引用渠道配置。`protocol` 必填，取值为 `chat`、`responses` 或 `anthropic`，程序按这个字段选择协议。

OpenAI 渠道 URL 保留 `/v1`。Anthropic 渠道由 SDK 在 URL 后追加 `/v1/messages`。作为参赛身份的模型必须配置角色名，仅用作测试替身的模型可以省略。

新任务统一通过普通 assistant 文本提交，不发送输出工具或原生 JSON schema 约束。已有工具选择 profile 配置继续保留，无工具请求不触发强制工具选择。

出价使用依次排列的 `<strategy>` 和 `<decision>` 块，标签独占一行；decision 正文是仅含 `bid`、`super_bid` 的 JSON 对象。发言使用 `<strategy>` 和 `<speech>` 块，记忆与观众总结直接返回正文。自然文本可正常分段，原始回复保存在审计中。

格式错误和业务校验错误共享一次纠错机会，每项任务最多发起两次逻辑请求。纠错后须重新提交完整结果。

网络重试单独计数：比赛中每次逻辑请求至多因可重试的网络或服务错误重发一次。完整回复流带有明确的成功结束标志后，程序才会交付结果；截断回复直接失败。输出预算策略见[常用调整](usage.md#常用调整)。

## 能力快照导入

已有 models.dev 数据文件时可离线更新：

```bash
python -m auction_game.cli.sync_models --input "path/to/api.json" --write
```

同步时，程序按 `configs/models.yaml` 中配置的 models.dev 精确来源匹配。省略 `--write` 时只预览结果；写入内容与原文件相同时，保留原文件。输出预算和推理档位的选择规则见[常用调整](usage.md#常用调整)。

## 连通检查参数

```bash
python -m auction_game.cli.check_llm --model "目录键" --max-tokens 2048
```

`--model` 可以重复传入，用来选择多个目录键。它不能与 `--test-model` 同时使用。两者都省略时，程序检查阵容实际会调用的所有模型；调用配置相同的目标只检查一次。

每个目标至多发起一次流式文本请求，校验约定的成功回复，没有重试，也不创建场次。探测只检查文本通道，比赛格式遵循度通过测试赛检查。

`--max-tokens` 必须是正整数，默认值为 2048。实际探测预算取该值与比赛输出预算中的较小值。连通检查不依赖 `game.yaml`，也不修改比赛预算。

**真实探测可能收费。** 用户可亲自运行上述命令。智能体获准排查后，每次至多执行一次最小请求，不自动重试；扩大检查范围需再次确认。完整费用边界见根 [AGENTS.md](../AGENTS.md#费用边界)。

## 完整请求捕获与回放

offline 场次会自动生成 `replay.md`。真实比赛默认关闭完整捕获。要为指定玩家开启，可通过 Python 调用 `auction_game.runners.run_ai(record_player=角色名)`；CLI 暂无开关。真实比赛仍由用户亲自启动。

完整捕获写入 `data/replay/`，保留失败请求、纠错请求，以及撤销本轮后留下的请求分支。重建时逐次还原模型实际收到的完整消息，使用哈希校验消息、响应和工具定义是否保持原样。未在启动时开启捕获的场次，之后无法补出完整请求。

已捕获的真实场次首次导出：

```bash
python -m auction_game.reporting.replay "logs/场次目录" "角色名" --capture-definitions
```

这一步使用本场配置快照、假密钥和 `MockTransport`，离线补充 SDK 工具定义，不调用真实服务。已有定义会直接复用。后续导出：

```bash
python -m auction_game.reporting.replay "logs/场次目录" "角色名"
python -m auction_game.reporting.replay "logs/场次目录" "角色名" --debug
```

回放默认展示开局、第一局第二天、首次跨局和终局等关键节点。程序还会从实际日志中选择流局后的奖池滚存、超级出价命中或落空，以及加赛等事件。回放里的回复均来自本场记录，不会重新生成。

来源和审计链接在页尾。加上 `--debug` 会额外把完整记录导出到 `debug/<玩家编号>.md`。缺少 SDK 工具定义时，程序会明确要求用 `--capture-definitions` 离线补充，不会静默使用当前 SDK 替换历史定义。

### 工具记录与来源

只查看工具定义时，无需开启完整捕获。场次的 `tools.md` 对应两份数据：`data/tool_requests.jsonl` 保存请求引用，`data/tool_definitions.json` 保存定义。引用中的 `task_id` 对应玩家任务记录，`request` 是逻辑请求序号，`attempt` 是网络尝试序号。

阅读时请区分来源：

- `http_pre_send`：真实 HTTP 请求发送前提取的工具字段。
- `offline_sdk_generated`：FunctionModel 离线赛通过 SDK 生成的定义，没有真实服务调用。
- `offline_sdk_mock_transport`：导出回放时离线补充的协议定义，与运行时捕获分开保存。

默认工具记录只提取实际存在的 `tools`、`tool_choice` 和 `parallel_tool_calls` 字段。文本任务通常保存空定义 `{}`。字段缺失、值为 `null`、值为 `false` 会分别保留。失败和网络重发也保留请求引用。默认工具记录不保存完整请求 body。

完整捕获保存的是运行时传给模型的逻辑消息与参数，不是 HTTP 报文。回放中离线补充的工具定义有独立来源标记。

场次格式继续使用版本 3；回放支持旧工具消息和新文本回复。历史原文保持原样，包括字面反斜杠转义；需要导出旧场次时，先复制到临时目录再操作。

### 日志写入与隐私

一项任务的所有成功日志写入后，程序才会更新玩家内存状态。写入错误会继续向上传递。多个文件之间没有事务，出错时可能留下部分日志。

请求失败、中断或本轮撤销后，已有审计记录仍会保留，排查时要结合任务状态和结算记录阅读。

工具记录和完整捕获均不保存密钥或鉴权头。完整捕获包含私有策略、思考或记忆等内容，分享日志前请检查。

## 离线赛与运行环境

`offline_demo` 使用按固定脚本回复的假模型。模型任务失败时，程序先保存审计和所选玩家的完整捕获，再退出；失败场次可以用上述命令离线导出回放。可选参数：

- `--test-model`：使用测试替身配置，仍完全离线。
- `--player "角色名"`：选择捕获与回放玩家，默认阵容第一位。
- `--output "全新目录"`：指定输出目录。目录已经存在时会报错，不会覆盖。

默认配置会演示以下过程：第一天流局，超级出价落空；第二天使用滚存奖池，多人超级出价命中；正赛结束时第一名并列，再通过一次加赛决出第一。

报价按任务实际对应的局数和天数生成，首日报价仍使用规划阶段保存的缓存。这套脚本要求至少四名玩家，每局至少两天，至少两局正赛，并且允许加赛。经济参数也要足够支付报价和超级出价成本。

其他配置会使用一套合法的备用策略：首位玩家根据余额低价参与，其余玩家出 0。所有策略和回复都由假模型生成，不产生真实服务请求。

`main.py` 成功完成或由用户主动中止时，返回 0。已处理的启动错误返回 1，参数错误返回 2。

从其他目录运行 `main.py` 时，可以使用绝对路径。运行 `python -m` 工具时，项目需要位于模块搜索路径中。例如，在 Git Bash 中设置 `export PYTHONPATH='C:\project\auction-game'`。
