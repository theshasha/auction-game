# 比赛日志的统计说明

每日拍卖的赢家获得当日奖池分数。超级出价每命中一次，另加本场 `super_hit_score` 分。排名和单局最高分都按总分统计。

运行 `python -m auction_game.reporting.analyze` 时，程序从真实 `ai` 和 `ai-test` 场次中选择最新有效的一场。两种类型同等参与选择，无效场次会被跳过。要分析其他类型，指定 `logs/<场次>/`。

命令读取 `data/matches/<补零编号>.json`，打印全场汇总和玩家统计。

## 输出位置与格式

输出分为四个部分：

1. **比赛概况**：显示场次目录、运行类型、角色身份与实际调用模型，以及参赛名单。随后列出已完成局数、拍卖天数和流局比例。
2. **经济与超级出价**：显示局末金币、撞车损失，以及超级出价的使用情况和效果。成本、悬赏和超级出价净金币变化分别成行。接着显示每日平均出价、平均奖池和获胜价统计。
3. **玩家明细**：按总分降序排列，每名玩家一个小块。拍卖分与超级命中分分别展示，次数和金币均标明单位。
4. **特殊情况**：显示非法出价总笔数、出 0 总笔数和 0 价获胜次数。

结果使用纯文本输出。玩家名单和比赛参数都取自本场日志，不读取当前的 `game.yaml`、`players.yaml` 或 `config.yaml`。

真实 AI 场次分别显示角色身份和实际调用模型。offline 场次会明确标注实际使用假模型，配置中的型号另行列出。Bot 标为本地程序。

## 日志要求与参数来源

分析只支持格式版本 3。旧日志保留原样，不迁移。读取时会检查以下要求：

- 比赛参数和必需结算字段必须齐全。缺失时直接报错，不从当前配置补值。
- 初始金币、日工资、超级出价成本和悬赏逐局取自快照，用于重算余额和经济统计。出价上限取 `max_bid`，加赛列号为局号减去 `regular_matches`。
- 同一场次的各局参数和参赛名单必须一致。每天的正常出价、该局 `auction_scores` 和 `scores` 必须覆盖同一名单，名单顺序可以不同。两个分数字典的值都必须是非负整数，拒绝 bool。
- 奖池滚存、每日得分、每局成绩和累计排名必须一致。流局日获得的超级命中分也计入成绩。
- 每局必须按顺序完整包含第 `1..game.max_days` 天。缺天、重复、乱序或越界都会报错。
- 局号必须是唯一的正整数。文件的数字编号必须与内容中的 `match_index` 一致。文件按数字编号读取，重复局号直接报错，错误会指出具体文件或局号。

未完赛场次也可以分析，但只统计已经完整保存的局。文件必须从第 1 局起连续保存，每局都要包含累计排名。

## 每局分数矩阵

每名玩家的“各局总分”取自 match 的 `scores`，“各局拍卖分”取自 `auction_scores`。两者都覆盖全部正赛和加赛，用 ` / ` 分隔。统计结果中对应的字段分别是 `score_matrix` 和 `auction_score_matrix`。

玩家明细开头会统一标明列顺序，例如 `正赛第 1 局 / 正赛第 2 局 / 加赛第 1 局（总第 3 局）`。各局结束余额也使用这个顺序。

## 玩家明细

每名玩家一个小块，按总分降序排列，同分时按名字排序。各项定义如下。

### 总分

match 的 `scores` 跨局合计，行字段为 `total_score`。同时展示拍卖分 `auction_score` 和超级命中分 `super_score`。

`super_score = total_score − auction_score`。

### 单局最高总分

分别统计独占最高总分的局数和并列最高总分的局数。每名并列者都记完整一局。全员 0 分时，每人都记一局并列最高。

统计覆盖正赛和加赛。是否需要加赛，仍按正式比赛规则判断。

### 超级出价使用、命中和命中率

使用次数和命中次数取自 `super_uses`。命中率为命中次数除以使用次数，例如 `使用3次，命中2次（67%）`。

没有使用时，只显示使用 0 次、命中 0 次，不计算或展示命中率。

### 超级出价净金币变化

`命中次数 × 本场悬赏 − 使用次数 × 本场固定成本`。

单位为金币，显示正负号。这里只计超级出价直接带来的金币变化，正常出价扣款另计。

### 撞车损失

因撞车被没收的正常出价金币之和。这里只计正常出价，与全场汇总的口径一致。

### 平均正常出价（不含流局日）

取非流局日全部正常出价记录的 `bid` 均值，包括不符合规则的提交被改成的正常出价 0。流局日和超级出价均排除。

### 各局结束余额

根据本局收支重新计算，逐局列出，单位为金币。

### 非法出价

出价记录中 `status == "illegal"` 的次数。

### 正常出价为零（含非法转0）

正常出价为 0 的次数，包括流局日，以及不符合规则的提交被改成的正常出价 0。超级出价 0 不计入。

## 聚合口径

### 每日及全天平均出价

排除流局日后，取全部出价记录的 `bid` 均值，包括超级出价的目标价位，以及不符合规则的提交被改成的正常出价 0。

“每日”按第几天分组，合并各局同一天序号的记录。“全天总体”把全部非流局日的出价记录放在一起求均值，每笔出价等权。

超级出价的狙击数值参与这个均值，但实际金币消耗仍为快照中的固定 `super_cost`。因此，这里的取值范围和分母与玩家“平均正常出价”不同。

### 平均奖池

合并各局同一天序号的全部记录，取实际奖池均值。流局日也参与，奖池包含之前流局滚存的分数。

### 局末平均金币

每局从快照中的初始金币重新计算。第 2 天起加日工资，扣除获胜或撞车的正常出价，再扣超级出价固定成本、加命中悬赏。

每名玩家在每局结束时的余额都算一个样本，等权求均值，同时显示最低和最高余额。

### 撞车扣款、超级使用和命中

均包含流局日。撞车扣款只计正常出价，超级出价成本单独展示。撞车损失的“每局平均”为全场撞车损失除以已完成局数。

超级出价总成本为 `使用次数 × super_cost`，悬赏发放总额为 `命中次数 × super_bounty`。全场命中率按总命中次数除以总使用次数计算，没有使用时不展示命中率。

### 超级出价净金币变化

`全场悬赏发放总额 − 全场超级出价成本总额`。

该值等于各玩家超级出价净金币变化之和。

### 使用超级出价天数

当天 `super_uses` 非空就计一天。同一天多人使用，也只计一天。流局日包含在内。

### 命中原本互撞价次数

逐笔检查 `super_uses` 中的命中记录。如果目标价在当天正常出价的有效 `bid` 中出现至少两次，就计一次。同一天多人命中同价时分别计数，流局日也包含在内。

只用正常出价判断原有撞车。超级出价不参与计数，不符合规则的提交已被改成正常出价 0，计算时仍使用 0。判断时不使用 `raw_bid`，也不使用历史 `collision_values`。

### 改变当日结果天数

计算步骤如下：

1. 固定历史中每笔有效正常出价的 `bid`，移除当天全部超级出价。
2. 使用引擎中的同一套判定方法，只计算正常出价的撞车情况和赢家，不进行扣款或发奖。
3. 把重新计算的赢家或流局状态与历史结果比较。发生变化就计一天。

每天最多计一次，只统计全场天数，不把效果分配给某名玩家。超级出价落空、命中低价或命中本来就有多人撞车的价位，通常不会改变赢家。当天正常出价全部被超级出价命中而导致流局时，也可能计入。

不符合规则的提交已被改成正常出价 0，计算时仍使用 0。计算时不重新校验 `raw_bid`，也不沿用原 `collision_values`。这里只比较当天结果，不推演余额、奖池滚存或未来出价，历史日志保持原样。

### 出 0 总笔数

统计全部出价记录中 `bid == 0` 的次数，包括流局日、超级出价 0，以及不符合规则的提交被改成的正常出价 0。

玩家明细只计正常出价 0，所以逐玩家相加可能小于全场总数。0 价获胜次数只计非流局日的获胜价。

### 拍卖天数与获胜价

总拍卖天数是全部已完成局的天数之和，流局比例为流局天数除以总拍卖天数。

获胜价统计只包含非流局日。平均获胜价按各获胜日等权求均值，分布按价格统计获胜天数。“获胜价等于出价上限”的占比为获胜价等于 `max_bid` 的天数除以获胜日总数。
