# 团队赛

两个阵营各 3 人对抗，胜负只看阵营总分。和个人赛的不同只有两处：按阵营总分定胜负；超级出价只命中对方阵营的正常出价。私信和个人赛相同，见 `docs/letters.md`。

个人赛规则以 `RULES.template.md` 为准，经济参数的取舍见 `docs/rule-discussion.md`。

## 赛制

- 固定 2 个阵营、每队 3 人，阵营数和人数不做成可配置：
  - 经济参数是按 6 人调的，"命中只看对方阵营"的重算也按 3:3 分组；
  - 两个阵营之间是零和的，跨阵营约定不会让两边都占便宜（见 `docs/letters.md` 的"送分"）；分成 3 个阵营时，两个阵营可以联手送分压过第三方，同分时还要处理三方并列。
- 阵营总分是 3 名队员的总分之和，胜负只看阵营总分。正赛后两队总分相同就全体加赛，每局加赛后重新比较；加赛上限取 `game.yaml` 的 `max_playoffs`，到上限仍相同算平局。
- 经济参数沿用 `configs/game.yaml`，`--test-model` 照用 `test_model_overrides`。看过测试赛数据再决定要不要调。
- 每名玩家的流程和个人赛相同：各自的对话历史、局末记忆和下一局规划，每天自己出价，全员公开发言。

## 规则

### 命中只看对方阵营

规则正文替换 `RULES.template.md` 第四节的第 1、2 条：

> 1. 命中：超级出价只命中对方阵营的正常出价。狙击的价位上有对方阵营的正常出价，就算命中，否则落空。
> 2. 撞车：一个价位有 2 笔及以上正常出价，这个价位上的正常出价全部撞车；被超级出价命中的正常出价也撞车。撞车的正常出价失去获胜资格。

只狙到队友的价位时落空，队友的出价不受影响。有对方的正常出价时照常命中；同价位上狙击者队友的出价不算被命中，但和对方同价，照样撞车。所以超级出价不会让队友多撞车。

撞车分成两句写，是为了让"超级出价只打对方、队友撞车只因为和对方同价"读得出来。写成"被超级出价命中的价位上，正常出价全部撞车"，判定结果相同，读起来却像狙击既对队友无效、又烧掉了队友。

原因：按个人赛的命中规则，队友之间能零风险刷分。A 正常出 0，B、C 都狙击 0，每天白拿 2 分；再让 A 狙击 B 出的 1，花 1 金币就能拿 3 分。一局能刷 10–15 分，而整局拍卖奖池只有 14 分。

个人赛可以看成每人自成一个阵营，两种命中规则的判定结果相同，因为规则禁止超级出价和自己的正常出价相同。

### 金币归个人

队友之间不能转账。合并成阵营金币池后，三人的钱可以集中到一人身上出高价，打破"攒钱需要出口，但不能成为一等策略"这条边界，出价校验也要改。

### 规则正文

- 团队赛的模板是 `RULES_TEAM.template.md`。团队赛入口在创建日志和请求模型前生成根目录的 `RULES_TEAM.md`，`python -m auction_game.cli.rules --check` 两份都检查。场次目录里的规则文件仍叫 `RULES.md`。
- 第一节改为阵营赛制：列出两个阵营和各自的队员，胜负只看阵营总分，同分加赛，到上限算平局。
- 第二节写明金币归个人，不能转给队友。
- 第四节第 1、2 条换成上面的正文。结算例子里的阵营叫 A 队、B 队，和本场阵营无关，覆盖三种情况：只狙到队友的价位算落空；跨阵营命中；同价位上狙击者的队友没有被命中，但和对方同价，照样撞车。第三种要写明，否则模型可能刻意避开队友的价位。
- 第三、五节和个人赛逐字相同，包括私信，由测试检查。
- 规则和提示只写事实，不提示阵营怎么配合，原因见"未采用的方向"。

## 阵容和配置

- `configs/teams.yaml` 写两个阵营。每个阵营有阵营名和 3 名玩家，玩家写 `model`、`persona_title`、`persona_text`，`name` 可选，含义和 `configs/players.yaml` 相同。
- 混编和同模型的队伍都支持。同一个模型放多名玩家时，给每人写 `name`。
- 启动时检查：正好 2 个阵营、每个 3 人；阵营名非空且不同；玩家名的要求见 `docs/letters.md` 的"名字"。
- 不用预测胜率。`teams.yaml` 没有 `predicted_win_rate`，`prompts.enable_predictions` 对团队赛不起作用。人设和写作要求的开关照旧生效。
- `--test-model` 时 6 人都换成 `config.yaml` 的 `test_model`，名字和人设不变。

## 身份

系统提示的身份一节写明自己所属的阵营、两名队友、对方阵营和三名对手，例如"你叫 甲，属于 A 队，队友是乙、丙；对方是 B 队：丁、戊、己。"身份里不重申"只比阵营总分"，规则第一节已经写了。

## 显示

- 排名表先列阵营排名，再列每名玩家；玩家表保留个人名次，多一列阵营。规则只写"胜负只看阵营总分"，不写"没有个人排名"，两者不矛盾。
- 出价请求里的累计总分写成一行，按阵营分组，阵营后面的括号里是队员的分数。
- 出价请求的昨日明细在玩家后面加一列阵营。
- 本人的超级出价落空、而狙的价位上只有队友的正常出价时，"昨日你的金币结算"写明原因，例如"4 上只有你的队友乙，所以落空。"同一张表里明明有人出了这个价，只靠规则，模型可能以为结算出错，或以为对方没出这个价；私信的经验也是只写在规则里不够，见 `docs/letters.md` 的"规则"一节。
- 局末出价日志照旧按玩家列，玩家按 `teams.yaml` 的顺序排，同一阵营相邻。
- 加赛说明写两个阵营总分相同。终局宣布获胜阵营，或者平局。

## 入口和日志

- 命令是 `python main.py --team`，加 `--test-model` 时全员用测试模型。假模型完整赛是 `python -m auction_game.cli.offline_demo --team`。
- 场次类型是 `team`、`team-test` 和 `team-offline`，分别对应个人赛的 `ai`、`ai-test` 和 `offline`。
- 文件布局和个人赛相同。`players/` 按 `teams.yaml` 的顺序编号，前 3 个是第一个阵营；场次 README 按阵营分组列出私人对话。

## 统计

- `analyze` 不带参数时取最新的真实比赛，包括 `team` 和 `team-test`，从配置快照判断场次类型。
- 团队赛多给阵营总分，口径见 `docs/analyze.md` 的"阵营总分"。阵营指标（队内撞车次数、被对方命中的次数、只狙到队友价位的落空次数）看过测试赛再定。

## 实现要点

- 个人赛按每人自成一个阵营处理：命中、并列和加赛都按阵营判断，个人赛的判定结果不变；只有显示按赛制分开写。
- 阵营从三处取，各处看自己手上的数据判断是不是团队赛：
  - 系统提示和规则正文从阵容取，看 `Lineup.teams`；
  - 每轮的请求、排名表和终端从排名取：每条 `StandingsEntry` 带 `team`，个人赛为 `None`，不另传阵容；
  - 场次 README 和统计从场次快照里玩家的 `team` 取。
- 阵营排名只由 `auction_game/game/engine.py` 的 `team_standings` 汇总，提示、排名表、终端和统计都调用它；判断第一名是否并列用 `auction_game/game/tournament.py` 的 `ranking`。
- "被命中"只算对方阵营的狙击：同价位上狙击者队友的出价记作撞车，不记被命中，出价请求里本人金币结算的说法和规则一致。
- 统计只对快照里玩家带阵营的场次读累计排名：较早的个人赛日志里，累计排名的字段和现在不同。

## 要看测试赛数据的

- **起手趋同**：同一个模型写的开局可能完全一样。一次推演里，两个模型各自给出的第 1 局第 1 天都是正常出价 8、5、2，超级出价两笔打 0、一笔打 9，结果三个价位全部撞车、狙击全部落空、流局，每边付 24 金币。玩家第 1 天之后会按结果调整，但每局第 1 天仍可能撞成一样。经常出现时，再考虑给每个阵营一个三人共享、对方看不到的随机数。
- **单场波动**：读准对方三笔正常出价，一天能 6 比 0；三人集火同一价位，读准一次就得 3 分。
- **队友撞车和分工冲突**：队友同时写信，信又晚一轮才到（见 `docs/letters.md` 的"时序的取舍"），队友之间可能撞车，或者分工互相冲突。
- **分工被看穿**：两边都分主攻、接应、游击时，价位区间容易被看穿，主攻互相被打掉，流局变多，拍卖分缩水。这是推测。
- **金币松紧**：掩护的队员出价低、花得少，金币可能变松，超级出价可能变成每天的固定动作。`docs/rule-discussion.md` 里使用率的警戒线是 85%。
- **命中率**：打掉对方最高价往往直接把拍卖交给自己人，但命中率会下降，超级出价用得更多还是更少还不确定。
- **只狙到队友价位的落空**：出价请求里有就地说明，看模型会不会因此刻意避开队友的价位，或者仍以为对方出了这个价。

把个人赛的出价按全部 10 种 3:3 分组，用"只命中对方阵营"重新结算：

| 场次 | 个人赛命中率 | 按阵营重算 |
| --- | --- | --- |
| `logs/archive_20261028/` 下的 `20261026_190107_ai` 和 `20261020_210047_ai`，35 天，152 次超级出价 | 30% | 平均 15%，各分组 12%–20% |
| `logs/archive_20261018/20261018_213717_ai`，25 天，105 次 | 42% | 平均 27%，各分组 22%–32% |

这组数按的是个人赛的出价分布。团队赛里两队有协调，实际命中率可能更高，也可能更低。

## 未采用的方向

- **指挥官模式**：每个阵营由一名不出价的指挥官在局前给队员写提示词，局内不能干预。提示词是唯一的控制手段；每天只决定几个整数、信息全部公开、两个阵营你得我失，写得好的指示就是一段条件规则；两边队员是同一个模型，指挥官只有写得更具体才能占优。提示词最终会变成一份出价程序，比赛就成了写程序。限制提示词（不准写数字、限制字数、不准规定价位）没法可靠校验，换个说法就能绕过。
- **指挥官或一名模型替三人出价**：三名玩家变成一个决策者，没有了各自判断、靠交流配合。
- **3 个阵营各 2 人**：见"赛制"。
- **队友命中也算分**：会被用来刷分，见"命中只看对方阵营"。
- **误伤但没有奖励**：命中和撞车照个人赛，只有价位上有对方阵营的正常出价时才给悬赏和命中分。规则第四节第 1、2 条能和个人赛一字不差，但只狙到队友的价位会烧掉队友的出价，自己还白付成本；私信晚一轮才到，误烧队友赢面最大的一笔会很常见；命中情况还要分有奖励和没奖励两种。
- **在规则或提示里引导阵营配合**：身份里再重申"只比阵营总分"，和规则第一节重复，也就看不出规则本身够不够；提示"队友可以用私信商量分工"已经是策略指令，人设也明确不放策略，六个模型还会按同一个思路分工，更容易被看穿。测试赛要看的是模型自己会不会配合。
- **阵营共用金币池**：见"金币归个人"。
- **同一阵营打同一价位的多笔超级出价只算一笔命中**：两边都想到集火打 0 时会互相抵消，集火放大的是双方水平差距，算不上压倒性打法。
- **预测胜率**：要改成按阵营给，没有它也不影响玩法。
- **阵营前缀加名字的显示名**：名字写在配置里，同一场不重名，不需要前缀区分。
- **按阵营分目录的日志布局**：名字和阵营都在配置里，沿用 `players/` 编号，README 按阵营分组就够看。
- **测试赛加两项统计**（跨阵营正常出价撞车次数；同一阵营多笔狙击打同一价位的次数和命中数）：暂不需要。
