# 信件

个人赛有私信：玩家可以给其他玩家写信，除收件人外，其他玩家看不到。团队赛不用私信，用队内信件区，见 `docs/team-mode.md` 的"队内信件区和开局讨论"。邮箱、分块格式和送达提醒两边共用。

本文写现行机制，规则正文以 `RULES.template.md` 和 `RULES_TEAM.template.md` 为准。时序和送分的取舍见 `docs/design/rules.md`，没有采用的方案见 `docs/design/rejected.md` 的"私信"，测试赛结论见 `docs/design/playtests.md`。

## 规则

规则正文见 `RULES.template.md` 第五节第 5–7 条。信一律在收件人的下一次请求里送达：全员按同一串请求进行，下一次请求对每个人都是同一个环节。

整理记忆不写信，所以第 2 局起的开局规划收不到信。两局之间的私下沟通只有局末发言时写的信，下一局还要用的内容由收件人写进记忆。

送达时机除了写在规则第 6 条，写信和收信时还各提醒一次，见"写信时的提醒"和"收信"两节。只写在规则里不够：测试赛里有人在出价时写信，要对方"今天"避开某个价位；收信人也把出价后才收到的信，说成看过信才出的价。

## 格式

沿用分块格式，私信块放在原有两块之后，标签是收件人的名字，不写信就没有私信块。格式说明和报错在 `auction_game/agent/text_output.py`。

- 规划请求和发言请求附完整格式，第 2 天起的出价请求只附一句：每次都附完整格式太长，而本局规划请求留在对话里，直到局末整理记忆才清空。纠错时附完整格式。
- 长度只写在提示里，程序不检查，原因见 `auction_game/agent/AGENTS.md`。
- 解析时只把单独占一行、名字是本场玩家的标签当作块的边界，所以正文里单独一行写成某个玩家名字的标签，也会报格式错误。

### 名字

玩家名就是私信标签。阵容配置可以给每名玩家单独写名字，不写时用模型目录里的角色名。同一个模型放多名玩家时，靠这个字段区分。

读取配置时检查最终使用的名字，包括目录里的角色名：是非空字符串，不含空白和 `<`、`>`、`/`，不能是 `strategy`、`decision`、`speech`、`队内信件区`，同一场不重名。

## 写信时的提醒

可以写信的请求在任务提示之后、格式说明之前，写明这次写的信什么时候送到，文案在 `auction_game/agent/prompts.py`。

只写"收件人下一次行动时才收到"不够具体：团队测试赛 `logs/20261104_154754_team-test` 里，出价时写的 61 封信约有 11 封仍要求队友当天怎么出，最后一局最后一天的 4 封全是这样，到最终感言时才送到。

提醒还写明信到达时对方已经知道什么。同一场的这 61 封信，按关键词粗数，51 封先报自己当天的出价，8 封要求先互报余额或回信确认，还有人替队友猜明天的余额，都是把私信当成了实时聊天。信晚一轮才到时，写死的数字到达时往往已经过时，能传的是只依赖公开信息的规则。

## 收信

收到的信接在请求的事实信息之后、任务提示之前，写法和其他玩家的公开发言一致，标题写明信是在哪一环节写的，没有收到信时没有这一段。每个请求收到的信都来自收件人上一次行动的那一轮，所以标题按请求固定，文案在 `auction_game/agent/prompts.py`。

整理记忆的请求里，这一段接在其他玩家的局末发言之后。

## 人设

人设约束发言和私信的口吻。私信写给其他玩家，观众也会看。系统提示里的人设本来就没有限定只用于发言，提示不用改。

## 送达

- 待送达的信放在一个邮箱里。每一轮开始前从邮箱读出这一轮要送达的信，作为这一轮任务的固定输入，邮箱本身不变；这一轮结果提交后，才一次性去掉已送达的信、放进这一轮新写的信。所以补跑的任务看不到同一轮其他人刚写的信；中途退出时，邮箱仍是轮开始时的状态。
- 局末发言时写的信在整理记忆时送达。整理记忆后对话清空，信的原文不再保留。

## 日志

- `players/`：写信人的结果里多一节"私信"，收信人的请求里有收到的信。
- `letters.md`：每轮结果提交后，有人写信就追加一节，标题是写信那一轮的名称，每封信写成"【甲 → 乙】内容"，写信人按配置顺序。文件开头说明信在收件人下一次行动时收到，免得把节标题读成收信的时候。第一次有人写信时创建；场次 README 和 `speeches.md` 一样，在每局结束更新时加上链接。
- `speeches.md` 只放公开发言和观众总结，`matches.md` 只放出价表和排名。
- 终端不打印私信，一天最多 12 封，太长。
