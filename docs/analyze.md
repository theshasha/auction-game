# 对战日志的玩家统计口径

`python -m auction_game.reporting.analyze` 默认从真实 `ai` 与 `ai-test` 场次中读取最新有效的一场，两种类型同等参与选择；跳过无效场次。显式传入 `logs/<场次>/` 可分析其他类型。比赛数据位于 `data/matches/<补零编号>.json`，打印聚合统计和玩家统计。

## 输出位置与格式

玩家统计位于聚合经济块（撞车扣款、超级出价）之后、“单局 ≥3 胜场”列表之前。
使用纯文本输出，玩家名单与比赛参数均取自日志，不读取当前的 `game.yaml`、`players.yaml` 或 `config.yaml`。
必须有新格式 `data/run_config.json`，先展示运行类型并核对参数和名单；AI 显示身份模型及实际执行模型，测试模式明确标为“非身份模型成绩”。默认排除 Bot 与 offline，保留所选场次的真实类型及模型信息；旧格式明确报错，历史原地保留。

## 日志要求与参数来源

- 只支持当前日志结构：每局 `match.game` 保存完整的八字段参数快照（`initial_coins`、`daily_salary`、`daily_pool`、`max_bid`、`super_cost`、`super_bounty`、`regular_matches`、`max_playoffs`），每日包含 `collision_values` 和 `super_uses` 等结算明细。
- 缺参数或当前结构必需字段会明确报错；缺少 `super_uses` 不按零使用处理。旧版本号、顶层零散参数和旧撞车结构均无回退解释。
- 初始金币、日工资、超级成本与悬赏逐局从快照读取，用于余额重放和经济统计；出价上限取 `max_bid`，加赛列号为局号减 `regular_matches`。
- 同一场次各局必须有相同的参数与参赛名单；每日正常出价和该局 `wins` 也必须覆盖同一名单，加载时检查以防混场。名单顺序可以不同。
- 每局必须完整包含按顺序排列的第 `1..game.max_days` 天；缺天、重复天、乱序或越界均报错。局号必须是唯一的正整数，文件数字编号必须与内容 `match_index` 一致；文件按数字编号读取，不静默去重，错误指出具体文件或局号。
- 可以分析未完赛场次中已经完成的局，不要求未来局已经生成。分析只读场次快照并校验一次，每局余额只重放一次，供聚合统计与玩家明细共用；独立调用公开统计函数仍完整校验输入。
- 历史日志与验证记录保留，不执行迁移。

## 每局胜场矩阵

每名玩家一行、每局一列，单元格取自该局 match 的 `wins` 字段，覆盖全部正赛及加赛。

## 玩家明细

每名玩家一行，按总胜场降序排列：

1. **总胜场**：match `wins` 跨局合计。
2. **局冠军数**：每局胜场最高者为局冠军；第一名并列时每人按 `1/n` 计入。这是统计指标，正式比赛的加赛判定仍遵循比赛规则。
3. **超级出价使用、命中、命中率**：从 `super_uses` 统计，无使用时不计算命中率。
4. **超级净金币收益**：命中次数 × 本场悬赏 − 使用次数 × 本场固定成本。只计超级带来的直接金币变化，正常出价扣款另计。
5. **撞车扣款**：因撞车被没收的正常出价金币合计，只计正常出价，与聚合段口径一致。
6. **平均正常出价**：非流局日全部正常出价记录的 `bid` 均值，包含非法整单转换后的正常 0；排除超级出价与流局日。
7. **每局局末余额**：通过 `recompute_remaining_coins` 重算，逐局列出。
8. **非法出价笔数**：bid `status == "illegal"` 的次数。
9. **出 0 次数**：正常出价为 0 的次数，包含流局日及非法整单转换后的正常 0，排除超级出价 0。

## 聚合口径

- **每日及全天平均出价**：排除流局日，纳入全部出价记录的 `bid`，包含超级狙击数值及非法整单转换后的正常 0。超级狙击数值参与这个均值，实际金币消耗仍为快照中的固定 `super_cost`。因此聚合均价与玩家“平均正常出价”的分母和取值不同。
- **平均奖池**：同一天序号的全部记录均参与，包含流局日及其滚存后的实际奖池。
- **局末平均金币**：每局先按快照重置初始金币；第 2 天起加工资，扣除获胜或撞车的正常出价，再扣超级固定成本、加命中悬赏。每个玩家-局等权参与均值。
- **撞车扣款、超级使用与命中**：包含流局日；撞车扣款只计正常出价，超级成本单列。
- **超级净金币收益**：全场悬赏发放总额减去超级成本总额，等于各玩家超级净金币收益之和。
- **使用超级出价天数**：当天 `super_uses` 非空就计一天，同一天多人使用也只计一天，包含流局日。
- **命中原本互撞价次数**：逐笔统计 `super_uses` 中的命中；目标价在当天正常报价的有效 `bid` 中出现至少两次就计一次。同一天多人命中同价分别计数，包含流局日；超级报价不参与正常报价计数，非法整单转换后的正常 0 保持为 0，不使用 `raw_bid` 或历史 `collision_values` 判断原有互撞。
- **改变当日结果天数**：固定历史中每笔有效正常报价 `bid`，移除当天全部超级出价，再用引擎共用的纯判定重新计算正常报价互撞及赢家；与历史赢家/流局比较。每一天最多计一次，全场汇总，不逐人归因。落空、命中低价或命中本已互撞的价位通常不会改变赢家；当天正常报价被全部狙掉导致流局也可能计入。非法整单转成的正常 0 保持为 0，不重新校验 `raw_bid`，也不沿用原 `collision_values`。只比较当天结果，不推演余额、奖池滚存或未来出价，不改写历史日志。
- **单局 ≥3 胜场**：固定以 3 为门槛，不随奖池或天数改为“过半胜场”。
- **出 0 总笔数**：全部出价记录的 `bid == 0` 次数，包含流局日、超级出价 0 及非法整单转换后的正常 0；玩家明细只计正常出价 0，因此逐玩家相加可能小于聚合总数。0 价获胜次数只计非流局日的获胜价。

## 验证

`tests/app/test_analyze.py` 使用合成日志离线检查当前快照、非默认参数、缺字段与混场拒绝、完整天序、重复局号与文件编号检查，并覆盖公开函数及 CLI 报错。默认选择回归覆盖两类真实 AI 场次、无效场次跳过、同秒数字后缀及 Bot/offline 排除，并核对测试场次的类型与实际模型输出。已有手写预期验证均价及出 0 口径、经济统计、玩家明细、加赛列号与输出顺序；未完赛场次的已完成局仍可分析。超级统计覆盖正负净金币收益、非默认经济参数、落空、低价命中、原有互撞、多人命中同价按笔计数、流局日互撞命中、流局变化、非法提交保留有效 0，以及不推演未来、不修改输入。`tests/game/test_engine_super.py` 另验证共用判定不修改报价记录，引擎原有超级规则回归继续运行。

旧实现的历史验证结果见 [2026-09-09 玩家统计验证记录](history/2026-09-09-analyze-verification.md)，其旧格式支持结论仅适用于当时实现。
